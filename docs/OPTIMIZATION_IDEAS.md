# FoxDroid 优化想法

> 记录日期：2026-10-04
> 状态：想法收集；Android 音频准备性能优化依用户决定移至最小 MVP 之后。

## 浏览器端

1. **独立校准页面**：为浏览器端提供专门的校准页面。具体校准项目、交互和验收标准以后再定。
2. **按键反馈**：当前浏览器端按下按键时缺少视觉和听觉反馈；后续考虑补充。反馈形式和时序以后再定。
3. **界面方向**：希望 UI 的观感与 Project OutFox 更接近。具体参考范围和设计方案以后再定。

以上仅记录用户提出的方向。开始设计或开发前，再明确范围、优先级与验收标准。

## Android：音频准备等待过长

- 用户反馈（2026-10-04）：两三分钟的真实歌曲预解码等待很长，可能超过歌曲时长，阻碍正常选曲和验收。属于待测量的性能问题，不是可接受的长期体验；磁盘缓存修复只解决内存限制，没有证明准备速度达标。
- 状态：用户明确要求先完成最小 MVP；该优化移至 MVP 之后，不作为 A2/A3 当前开发门槛。届时先测量提取、解码、PCM 转换和缓存写入各阶段耗时，记录音频格式、时长、采样率、设备和构建版本，不上传用户曲包。
- 开发方向：消除逐小块同步等待与重复数据转换/写盘；评估后台持续解码、短前导缓冲后开始播放，以及可复用的有界缓存。音频回调继续禁止解码、文件 I/O 和阻塞；缓冲不足必须可观察、可恢复，不能破坏判定时钟。
- 暂定验收目标（尚未实测）：目标真机上，两三分钟 WAV/MP3/OGG 的首次“准备并游玩”至可点击开始不超过 5 秒，同一音频再次准备不超过 1 秒；连续完整游玩无缓存缺帧。至少两台目标机、每种格式重复三次，记录所有耗时及最差值。若目标不能满足，记录原因并重新评审，不能仅延长超时或提高内存上限算作修复。

对应排期见 [Android 开发计划](./ANDROID_DEVELOPMENT_PLAN.md)的 MVP 后优化。

## Android：补全音频格式兼容

- 用户反馈（2026-10-04）：NAS 曲库能够识别，但部分歌曲提示音频格式不支持；具体格式、编码和 MIME 尚未采集。曲库识别通过不代表所有歌曲可准备或游玩。
- 状态：用户明确暂不确定失败格式，要求先搁置到后续；列入 MVP 后兼容性优化，与预解码耗时问题分别跟踪。不要求用户现在排查格式，不宣称已修复。
- 范围：核对远程资源 MIME 白名单与本地扩展名限制，识别合法的 MIME 别名或通用二进制类型；以实际媒体轨道和编码判断可解码性。根据失败样本补全格式支持，区分容器不支持、编码不支持、元数据误标和文件损坏，并给出具体错误提示。不能只放宽白名单而不验证解码。
- 验收：使用原创或许可明确的不同容器/编码素材，覆盖本地导入和 NAS 下载、准备、完整游玩；记录格式、编码、MIME、设备与结果。已支持格式不回退；损坏或确实不支持的文件应明确报错。用户曲包不上传公开仓库。
