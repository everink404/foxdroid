# FoxDroid 产品需求文档

> 状态：初稿  
> 版本：0.4  
> 日期：2026-09-08  
> 产品工作名：FoxDroid

## 1. 产品概述

FoxDroid 是一个由家庭内容服务、内置 Web 客户端和可连接的 Android 原生客户端组成的节奏游戏平台，支持读取 StepMania / Project OutFox 生态中的常见歌曲包和谱面。

产品覆盖三个场景，并按以下顺序交付：

1. 优先：在 Android 手机上通过多点触控游玩。
2. 优先：在 Windows、macOS 或 Linux 浏览器中打开 NAS 提供的 Web 客户端游玩。
3. 后续：在 Android TV 或电视盒子上连接 USB 跳舞毯游玩。

Android 原生客户端必须可以独立运行。本地曲库是其基础内容来源；家庭内容服务器是设置页面中默认关闭的可选功能，用于从 NAS 统一管理和分发曲库。内容服务启用时同时提供 Web 客户端和客户端连接接口。服务端不参与任何客户端的实时输入和判定。

## 2. 产品目标

### 2.1 核心目标

- 首期在主流 Android 手机上提供稳定、低延迟的四键触控体验，并提供可直接从内容服务打开的 Web 游玩端。
- 首期兼容常见 `.sm` 和 `.ssc` 歌曲包。
- 首期支持手机触摸屏和 Web 键盘；浏览器游戏手柄作为增强能力，Android TV 遥控器和 USB HID 跳舞毯延后。
- 支持完全离线的本地曲库。
- 可选连接部署在家庭 NAS 上的内容服务器，共享同一曲库。
- 内容服务器自带浏览器可访问的 Web 客户端，无需安装桌面应用即可浏览和游玩服务器曲库。
- Web 客户端与 Android 原生客户端使用同一套公开、版本化的内容接口。
- 服务端不可用时不阻塞应用启动、本地选歌或已准备完成歌曲的游玩。

### 2.2 非目标

首期不以以下能力为目标：

- 完整复刻 Project OutFox 的全部 18 种游戏模式。
- 完整兼容 OutFox / StepMania Lua 主题、复杂 Mod 和编辑器。
- 云端公共曲库或商业音乐商店。
- 强制注册账户或依赖互联网连接。
- 让服务端参与游戏时钟、输入处理或实时判定。
- 支持 Tizen、webOS 等非 Android 智能电视系统。
- 承诺所有智能电视内置浏览器都能达到跳舞毯所需的输入与音频延迟。
- 让现有未经修改的 StepMania / ITGmania 客户端直接读取内容服务接口。
- Android TV 原生客户端、电视遥控器导航和 USB 跳舞毯支持；这些能力延后到独立 TV 阶段。

## 3. 目标用户

### 3.1 手机节奏游戏玩家

- 使用手机触屏游玩四轨谱面。
- 希望导入已有歌曲包并离线游玩。
- 可能在家庭网络中同步 NAS 曲库，也可能长期不使用服务端。

### 3.2 桌面浏览器玩家

- 希望在 Windows、macOS 或 Linux 上直接打开网页使用 NAS 曲库。
- 不希望安装或修改 StepMania 分支。
- 首期使用键盘，后续可使用兼容浏览器 Gamepad API 的手柄或跳舞毯。

### 3.3 家庭曲库管理员

- 在 NAS 上保存较大的 StepMania / OutFox 曲库。
- 希望只扫描和解析一次，让多台电视和手机共享歌曲清单。
- 能够通过 Docker Compose 或 NAS 容器管理界面部署服务。

### 3.4 家庭跳舞毯玩家（后续阶段）

- 拥有 Android TV、Google TV 或 Android 电视盒子。
- 通过 USB 连接一张或两张跳舞毯。
- 希望坐在沙发距离外使用遥控器完成启动、选歌和设置。

## 4. 产品原则

1. **离线优先**：不启用服务端时，客户端仍是完整可用的游戏。
2. **服务端可选**：首次启动不得要求填写服务器地址或部署 Docker。
3. **实时逻辑本地化**：播放时钟、输入时间戳、判定与计分全部在客户端完成。
4. **内容来源一致**：本地和远程歌曲使用一致的选歌、预览和游玩体验。
5. **移动与 Web 优先**：首期决策优先保证手机触控和桌面浏览器体验；电视适配不得阻塞 MVP。
6. **兼容优先于扩展**：先正确实现常用谱面语义，再增加格式和玩法数量。
7. **显式降级**：服务器、媒体或外设异常时给出明确状态，不静默失败。
8. **同源体验**：内置 Web 客户端与原生客户端共享内容模型和谱面语义，但允许按平台采用不同的输入和音频实现。

## 5. 核心用户流程

### 5.1 本地曲库流程

1. 用户启动应用。
2. 用户通过系统文件选择器选择歌曲目录、ZIP 或兼容歌曲包。
3. 客户端导入并解析内容。
4. 歌曲出现在统一曲库中。
5. 用户选择难度并开始游玩。

### 5.2 可选内容服务器流程

1. 用户进入“设置 > 内容服务器”。
2. 用户打开“启用内容服务器”开关。
3. 用户自动发现或手动输入服务器地址。
4. 客户端测试连接并获取服务器信息。
5. 客户端同步歌曲清单，不递归扫描 NAS 文件目录。
6. 远程歌曲出现在统一曲库中，并带有来源或可用状态标识。
7. 用户选择歌曲后，客户端请求游玩所需的谱面与媒体资源。

### 5.3 服务端异常流程

- 启动时服务器离线：进入本地曲库，并显示非阻塞状态提示。
- 浏览远程曲库时掉线：继续显示上次成功同步的清单，标记当前不可获取的内容。
- 准备歌曲时掉线：取消本次准备并允许重试，不进入无法完成的游玩界面。
- 游玩开始后掉线：如果歌曲已准备完成，当前游玩不得受影响。

### 5.4 Web 客户端流程

1. 用户在局域网浏览器中打开内容服务地址。
2. 服务返回 Web 客户端，客户端从同源接口读取曲库清单。
3. 用户通过键盘、游戏手柄或触摸完成选歌和游玩。
4. Web 客户端在开始前准备谱面和必要媒体，并在浏览器本地完成时钟、输入、判定与计分。
5. 浏览器或输入设备不满足要求时，显示能力诊断和降级提示。

## 7. 内容服务器需求

### 7.1 基础职责

- 在 NAS 本地文件系统中扫描配置的歌曲目录。
- 解析支持的谱面并生成统一曲库索引。
- 将扫描结果写入数据库，客户端不直接扫描共享目录。
- 提供服务器状态、曲库版本、歌曲清单和资源获取接口。
- 托管与服务端版本匹配的 Web 客户端静态资源。
- 支持增量更新，并能在管理员要求时执行完整重建。
- 通过只读挂载访问曲库，默认不得修改用户歌曲文件。

### 7.2 部署要求

- 提供 Docker 镜像和 Docker Compose 示例。
- 支持 amd64 与 arm64 NAS。
- 将曲库、数据库和配置分别映射为持久化目录。
- 容器重启后无需重新配置；数据库损坏时可以从原始曲库重建。
- 初始版本只要求单节点家庭局域网部署。
- 一个访问地址应同时提供 Web 客户端和版本化接口，避免用户额外部署 Web 服务器。

### 7.3 管理要求

- 提供健康状态和最近一次扫描结果。
- 显示已发现歌曲数、有效谱面数、错误文件数和扫描耗时。
- 单个损坏歌曲不得导致整次扫描失败。
- 扫描错误应包含可定位的相对路径和原因。

## 8. 非功能需求

### 8.1 性能

- 客户端启动不得等待远程服务器超时后才能进入本地曲库。
- 已同步清单应从本地数据库快速展示，不在主线程执行网络或文件扫描。
- 目标设备上游玩画面稳定在 60 FPS；支持高刷新率设备作为后续增强。
- 游戏期间不得执行完整曲库扫描、数据库迁移或大型后台下载。
- 音频回调线程不得执行网络、文件枚举、数据库查询或阻塞操作。
- Web 客户端应在前台可见状态运行；浏览器切入后台时自动暂停游戏。

### 8.2 稳定性

- 应用从后台恢复后不得继续使用失效的音频时钟或输入状态。
- 网络超时、资源缺失和解码失败必须可恢复。
- 客户端不得因为一个损坏谱面而无法加载整个曲库。

### 8.3 安全与隐私

- 服务端不得向客户端暴露 NAS 的绝对文件路径。
- 所有资源请求必须限制在配置的曲库根目录内。
- 密码或令牌不得出现在日志、崩溃报告和曲库数据库中。
- 默认仅在家庭局域网中运行，不假定服务直接暴露到互联网。
- 客户端需明确说明局域网权限的用途。

### 8.4 兼容性

- 初始建议支持 Android 10 及以上；最低版本在原型测试后最终确定。
- 发布包至少支持 arm64-v8a。
- 后续电视版本不得声明触摸屏为必需硬件。
- 不启用服务端时，不应要求局域网权限。

## 9. 内容与版权边界

- 应用不得未经授权捆绑商业歌曲、封面或视频。
- 用户自行导入内容与应用官方分发内容应在产品和法律上区分。
- StepMania 引擎源码、歌曲内容、第三方编解码器和主题资源分别遵循各自许可证。
- 未获得授权前不得使用 Project OutFox 的商标、默认主题或专有资源暗示官方关系。

## 10. MVP 范围

MVP 包含：

- Android 手机横屏四轨触控。
- 桌面浏览器 Web 客户端，首期支持键盘输入。
- `.sm`、基础 `.ssc` 与常用音频/图片。
- 本地曲库导入、选歌、游玩、结算和本地成绩。
- 设置页可选开启内容服务器。
- 手动服务器地址、连接测试、清单同步与资源获取。
- Docker 服务端扫描、数据库索引和只读内容接口。
- Docker 服务端直接托管 Web 客户端。
- 音频、视觉和基础输入延迟校准。

MVP 不包含：

- Android TV 原生客户端、遥控器导航及电视专项适配。
- USB 跳舞毯与双人舞毯。
- 公网访问和云账户。
- 服务端成绩同步。
- 完整视频、Lua 主题及高级 Mod 兼容。
- OutFox 全游戏模式。

## 11. 验收标准

### 11.1 独立客户端

- 全新安装且未启用服务器时，用户能导入一份有效歌曲包并完成一局游戏。
- 飞行模式下，本地曲库和已经准备完成的内容可以正常游玩。

### 11.2 可选服务器

- 开关默认关闭，关闭时没有后台服务器连接。
- 开启并输入有效地址后，可以看到服务器曲库而无需扫描 SMB 目录。
- NAS 关闭时，应用能在限定时间内进入本地曲库。
- 服务器曲库发生变化后，客户端能通过新清单反映新增、修改和删除。

### 11.3 输入与判定

- 手机可以正确处理至少四点同时触控。
- Web 客户端可以使用键盘完成四方向输入、长按和同时按键。
- 网络断开不会改变已经开始的歌曲的输入判定结果。

### 11.4 Web 客户端

- 在当前版本 Chrome、Edge 和 Firefox 桌面版中，可以从服务地址进入曲库并完成一局游戏。
- Web 客户端的谱面判定全部在浏览器本地完成。
- 不支持的输入设备或音频能力会得到明确提示，而不是进入不可玩的状态。

## 12. 衡量指标

- 首次进入可操作界面的时间。
- 本地与远程清单同步耗时。
- 选中歌曲到可开始游玩的等待时间。
- 音频 underrun 次数和画面掉帧率。
- 不同设备校准后的判定偏移分布。
- USB 输入设备映射成功率。
- 服务端扫描成功率及单曲解析失败率。

## 13. 待确认问题

1. MVP 是否只支持 `dance-single`，还是同时加入五键 Pump。
2. 最低 Android 版本和首批手机测试设备。
3. 远程歌曲是仅临时缓存，还是支持显式下载为离线歌曲。
4. 关闭内容服务器开关时，已取得的远程资源默认保留还是清理。
5. 是否需要在首版支持背景视频。
6. 是否使用 FoxDroid 作为正式名称。
7. 是否计划公开源代码，以及选择何种许可证。
8. Web 客户端首期是否只定位为桌面休闲游玩，还是纳入竞技级延迟目标。
9. Web 客户端是否需要承担服务端管理界面，还是管理功能保持独立页面。
10. Android TV 阶段何时启动，以及电视端是否沿用手机 APK 的共享核心。
