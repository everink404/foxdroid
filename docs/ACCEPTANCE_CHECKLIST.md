# FoxDroid 验收清单

> 更新：2026-09-30  
> 当前结论：M1 服务端与 Web 可运行原型，尚未达到 MVP。  
> 依据：[项目状态](./PROJECT_STATUS.md)、[产品需求](./PRD.md)、[开发规划](./DEVELOPMENT_PLAN.md)。

## 如何使用

- `[x]` 表示已有可复查的证据；`[ ]` 表示仍需开发、实测或留存证据。
- 每项完成时记录设备/浏览器版本、测试曲包、结果和失败日志。自动测试通过不替代音画与设备实测。
- M1 可单独验收服务端与 Web 链路；完整 MVP 还需要 M0、M2、M3 和 M4 的门槛。

## A. 已有证据

- [x] `.sm` 与标准 `.ssc` 能解析并扫描成 SQLite 内容索引；损坏歌曲单独报错。证据：`server/tests/test_simfile.py`、`server/tests/test_scanner_database.py`。
- [x] 清单、歌曲、谱面、媒体和扫描接口具有基础自动测试；清单 ETag 与媒体 Range 已覆盖。证据：`server/tests/test_api.py`。
- [x] Web 时间轴和 Tap/Hold/Roll/Mine 逻辑有共享向量；覆盖 BPM、正负 Offset、Stop、Delay 和 Warp。证据：`shared/test-vectors/`、`server/tests/web_core.test.mjs`。
- [x] 原创黄金曲库包含 `.sm/.ssc` 优先级、谱面级时间标签覆盖、损坏文件和缺失音乐。证据：`shared/golden-library/`。
- [x] 本地自动检查通过：9 项 Python 测试、23 项 JavaScript 测试及 Ruff 检查（2026-09-30）。
- [x] 项目已建立 Git 历史并发布到 [GitHub](https://github.com/everink404/foxdroid)。

## B. M1：服务端与 Web 纵向切片退出门槛

### 部署与内容

- [ ] 在可用 Docker 环境从空数据目录执行 `docker compose up --build`；记录镜像、架构、启动时间和健康检查结果。
- [ ] 扫描黄金曲库后重启容器，确认 SQLite 索引持久化、曲库只读挂载、缺失素材和损坏歌曲不阻塞其他歌曲。
- [ ] 验证 `linux/amd64` 构建；为 `linux/arm64` 实机构建或可执行验证留证。
- [ ] 建立核心依赖、参考代码、谱面与音频素材的来源及许可台账。

### 带音频游玩

- [ ] 使用合法生成的 WAV，在浏览器从打开曲库、选歌、准备音频到完成结算重复完成至少两局，记录浏览器版本与结果。
- [ ] 对照节拍实测音频播放、画面与按键判定；分别验证正负 Offset、判定偏移和视觉偏移，记录设备与偏移值。
- [ ] 使用实际 `.sm/.ssc` 曲包走通 Tap、Jump、Hold、Roll、Mine、BPM、Stop、Delay、Warp，并记录异常谱面结果。
- [ ] 歌曲与媒体准备完成后切断服务端或网络，确认本局可以结束且判定、分数不改变；新歌曲请求应有明确失败提示。
- [ ] 页面失焦、音频中断、重新进入页面时不沿用失效时钟，不出现错误判定或失控播放。

### 浏览器兼容

- [ ] 当前桌面版 Chrome：完成曲库、选歌、带音频游玩、结算，记录版本与差异。
- [ ] 当前桌面版 Edge：完成相同主流程，记录版本与差异。
- [ ] 当前桌面版 Firefox：完成相同主流程，记录版本与差异。
- [ ] 浏览器不支持音频或输入能力时，显示可理解的提示，不进入无法游玩的状态。

**M1 通过条件：**从空数据库启动到带音频结算可稳定重复；准备完成后断网不影响本局；三种桌面浏览器完成基础验证。当前不能勾选。

## C. 完整 MVP 前仍需开发

### M0：共同基础

- [ ] 建立 Android 工程，并让 Android 与 Web 消费同一份 API 草案和共享测试向量。
- [ ] 补齐 Hold、Roll、Mine 的实际黄金曲包、统一错误结构与版权/许可台账。
- [ ] 建立自动构建和持续集成，确保提交时运行 Python、JavaScript 与静态检查。

### M2：Android 手机纵向切片

- [ ] 全新安装、不配置服务端即可导入本地歌曲、四轨触控游玩并完成结算。
- [ ] 在至少一台 60 Hz 和一台高刷新率 Android 手机上验证四点同时触控、音频时钟、校准与生命周期。
- [ ] 内容服务开关默认关闭；开启后可以填写地址、连接、同步和游玩远程歌曲。
- [ ] 飞行模式与服务器离线时本地曲库可玩；已准备的远程歌曲断网后仍可完成。
- [ ] 后台切换和音频焦点变化不产生错误判定或失控播放。

### M3：兼容与内容同步

- [ ] 冻结 Tap、Jump、Hold、Roll、Mine 的正式判定和计分规则，并用同一输入序列验证 Web/Android 结果等价。
- [ ] 完成文件级增量扫描、删除传播、缓存失效和解析器版本迁移。
- [ ] 使用真实规模曲库测量扫描耗时、内存、NAS I/O 与清单同步，并验证单曲损坏隔离。
- [ ] API 与内容模型达到 `v1` 候选状态。

### M4：发行候选

- [ ] 完成服务端接口访问控制、异常输入、路径与 Range 请求安全检查，以及 Docker 备份、升级、重建验证。
- [ ] 完成 Android 权限、局域网拒绝、隐私、错误恢复及手机/Web 发布检查。
- [ ] 清零已知高严重度缺陷，满足 [PRD 第 11 节](./PRD.md#11-验收标准) 的手机、Web 和服务端标准。

## 本轮受限条件与下一步

- 当前开发机未检测到 Docker 或 Firefox，因此对应实测需要另一台设备或安装后执行。
- 优先顺序：**M1 带音频整局与断网验收 → Docker 实机 → Chrome/Edge/Firefox 矩阵 → Android 最小工程与真机链路**。
